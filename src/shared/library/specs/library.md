# library

## Purpose
墨读与 PDF 共用的那份书库：书目索引、导入判重、封面位置、阅读进度。
两个入口、一份数据，各存一份会出现"同一本书在两个入口各一本"
（见 [../architecture.md](../../../docs/architecture.md) §7.5、§8.2、§9）。
谁把元数据与封面读出来是各应用自己的事，书库只管存与索引。

### Requirement: 索引文件自己带版本，对不上就明说怎么办
不做静默迁移，也不留兼容字段：迁移代码是长期负债，自用阶段不背。

#### Scenario: LB-001 书库还空着时读到的是空表
- **WHEN** 共享区里还没有 `library.json`
- **THEN** 读出一张空表，不报错——第一次用与刚删干净是同一个样子

#### Scenario: LB-002 v2 的索引按原样读出
- **WHEN** 索引文件里写的是 `version: 2` 与若干本书
- **THEN** 每本读出来都带 id、标题、作者、格式、本体位置、封面位置、大小、进度与附加信息
- **AND** 落盘的文件里 `version` 是 2

#### Scenario: LB-003 版本对不上时报出该删哪个文件
- **WHEN** 索引文件里写着的 `version` 是 1
- **THEN** 读不出书目，错误原文以「书库索引是 v1，本包只认 v2。」开头
- **AND** 同一句里读得到「删掉 userData/shared/library/library.json」与「书本体和封面不用动」
- **AND** 没写 `version` 的索引同样被拒，念出来的是「书库索引是 v?，本包只认 v2。」

#### Scenario: LB-004 索引里 books 不是列表时单独报错
- **WHEN** 索引文件是合法 JSON，但 `books` 是个对象或缺失
- **THEN** 错误原文是「书库索引格式不正确」，不与版本不符那句话混用

### Requirement: 判重在拷贝之前
同一本文件重复导入不该在书库里留两份副本；
判重要早于拷贝，否则先拷再删会在 Windows 上留下删不掉的孤儿副本。

#### Scenario: LB-005 大小与标题都对上就算同一本
- **WHEN** 导入的文件大小与标题都和已有记录相同
- **THEN** 返回的是那条已有记录（id 不变），索引条数不增加
- **AND** 共享区里不出现第二份本体副本

#### Scenario: LB-006 只有大小对上不是同一本
- **WHEN** 导入的文件与某本大小相同但标题不同
- **THEN** 当成新书登记，新书有自己的 id 与本体副本

#### Scenario: LB-007 新书排在最前，本体落在 files/<书号>.<扩展名>
- **WHEN** 成功导入一本 `/某处/书名.epub`
- **THEN** 它排在书目最前面，记录里的本体位置是 `files/<id>.epub`
- **AND** 共享区那个位置上真有一份与源文件字节相同的副本，之后源文件删掉也不影响读

### Requirement: 封面由导入方交进来
书库不绑任何渲染库：谁导入谁把封面字节给它，谁先导入都行。

#### Scenario: LB-008 给了封面字节就存，没给也照样导入
- **WHEN** 一次导入带上封面字节，另一次不带
- **THEN** 前者的封面位置是 `covers/<id>.<扩展名>` 且文件存在，后者的封面位置是空
- **AND** 两次都登记成功——没有封面不是导入失败的理由

#### Scenario: LB-009 封面地址交给图片就能真画出来
- **WHEN** 一本书有封面，界面拿它的封面地址放进 `<img>`
- **THEN** 得到的是壳的界面允许加载的图片来源（应用窗口那条策略里 `img-src` 列出的那几种之一），书架上画得出来而不是破图
- **AND** 没有封面的那本得到空值，而不是一个指不到东西的地址

### Requirement: 删除连索引带文件一起清
书架上少一本，磁盘上就该少一本；留着副本等于让用户自己去找目录删。

#### Scenario: LB-010 删一本书把本体与封面一起删掉
- **WHEN** 从索引里删掉一本有封面的书
- **THEN** 索引里不再有这个 id，`files/` 与 `covers/` 下它那两个文件也不存在了
- **AND** 别的书的记录与文件一条都不被碰

#### Scenario: LB-011 删一个没登记过的书号什么都不动
- **WHEN** 拿一个不在索引里的 id 去删
- **THEN** 索引条数不变，共享区里的文件一个都不少，也不报错

### Requirement: 进度与附加信息是两个应用共用的一份
续读靠 `cfi`，没有就退回节号加节内比例；
每本的附加信息是开放键值，不给某个格式开专属字段（否则这个包就开始替一个应用说话了）。

#### Scenario: LB-012 进度四个字段存得下也读得出
- **WHEN** 给一本书写下节号 3、节内比例 0.25、CFI 与更新时间
- **THEN** 重新读出的四个字段与写进去的一致
- **AND** 再写一次空进度，这本书的进度就读不到了

#### Scenario: LB-013 墨读写的进度，PDF 读到的是同一份
- **WHEN** 墨读给某本书写了进度，另一个应用（PDF）从同一共享区读书目
- **THEN** PDF 读到的就是那一份进度，不是它自己的空值
- **AND** 两边各自筛自己的格式，看到的仍是同一批记录

#### Scenario: LB-014 附加信息各存各的键，互不干涉
- **WHEN** 一本 PDF 存了页数，另一本别的格式存了自己那几个键
- **THEN** 两本各自的键都读得出来，索引里没有为某个格式专设的顶层字段
- **AND** 更新其中一本的进度不改动另一本的附加信息

#### Scenario: LB-015 连续导入两本，后一次不吞掉前一次
- **WHEN** 一本刚登记完就导入下一本
- **THEN** 索引里两本都在，落盘的是一份完整可解析的 JSON
- **AND** 两次写盘各自排队，任何时候读到的都不是半截文件
