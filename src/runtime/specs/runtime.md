# runtime

## Purpose
窗口与直跑：runtime 自己没有界面，跑哪些包由命令行决定；一个应用一个窗口的规矩、窗口状态各记各的。
每个应用在自己窗口里做什么不在这里（见 `src/apps/airship-ffmpeg/specs/airship-ffmpeg.md`、`src/apps/airship-reader/specs/airship-reader.md` 等），
标题栏与主题的呈现见 `theme.md`；跨进程调用的规矩见 `bridge.md`。

> 只能在真机上观察的期望（单实例锁与第二实例转发的时序、一个应用崩了不带崩别人）记在
> [架构](../../../docs/architecture.md) §3，不在这本册子里充数。

### Requirement: runtime 只跑命令行指来的包
runtime 没有启动器、没有格子：`airship.exe <id>.airship` 注册一份、开一个窗口，可以一次指多份。
活动包表是进程级的，进程退出表就没了；下一次跑哪些包，由下一次 argv 决定。

#### Scenario: SH-030 没带包路径启动，念用法，不开界面
- **WHEN** 命令行里没有一个以 `.airship` 结尾的参数
- **THEN** 念出「airship runtime 不自己开界面：把一个包的路径交给它（airship.exe <id>.airship），或装一个应用后用它的快捷方式。」
- **AND** 解出来的包路径列表是空的，一个开窗请求都不发

#### Scenario: SH-031 相对包路径按交来那一侧的 cwd 解
- **WHEN** 第二实例转发来一个相对的包路径，它的 cwd 与第一实例的不同
- **THEN** 解出的绝对路径按转发方的 cwd 拼
- **AND** 绝对路径（快捷方式交来的）原样保留，不受 cwd 影响

#### Scenario: SH-032 不合格的包逐条拒，不静默少一个窗口
- **WHEN** 命令行指来的归档清单读不出来，或缺入口文件
- **THEN** 读得到「这个包跑不起来：<文件名>」，下面逐条「哪个归档：为什么」
- **AND** 判定与产包期是同一份，不存在"直跑判得松一点"

#### Scenario: SH-033 同 id 同归档是聚焦，异归档拒
- **WHEN** airship-life-game 已在活动包表里，再交来同一份归档
- **THEN** 返回的还是表里那一份，窗口动作是"聚焦已有窗口"，活着的 airship-life-game 窗口始终只有一个
- **AND** 同 id 交来另一份归档时拒，念「同一个 id 已经跑着另一份包：airship-life-game 现在用的是 <旧路径>，这次交来的是 <新路径>。先关掉它的窗口再跑这一份。」

### Requirement: 一个应用一个窗口，窗口之间各过各的
窗口是隔离单位：同一个应用只开一个，关窗要把它名下的摊子收干净。
任务栏那一颗按钮的身份、图标与重启动作都**逐窗口**给——进程级那一份只会把八个应用拧成一颗按钮。

#### Scenario: SH-006 关掉应用窗口，它名下的子进程跟着收掉
- **WHEN** 一个应用在跑一条真命令（子进程还活着），把它的窗口关掉
- **THEN** 该应用名下在跑的任务被逐个终止，返回被终止的条数
- **AND** 别的应用名下的任务一条都不被碰

#### Scenario: SH-007 窗口没了，归属随之解除
- **WHEN** 某应用的窗口关闭
- **THEN** 它的 webContents 不再认得出归属（`ownerOfContents` 返回空）
- **AND** 台账里它不再算"开着的应用"，可以再开一个新窗口

#### Scenario: SH-010 每个应用在任务栏是自己的一个条目
- **WHEN** 看某应用窗口的任务栏身份
- **THEN** 身份是 `dev.xyzwp.airship.<应用 id>`，两个应用的身份必然不同
- **AND** 每个身份都带应用 id 后缀：runtime 自己没有窗口，不存在不带后缀的第二个身份

#### Scenario: SH-034 任务栏那颗按钮带的是应用自己的图标
- **WHEN** 一个自带 `icon.ico`（PK-036）的包的窗口开起来
- **THEN** 交给外壳的图标是磁盘上的 `<userData>/icons/<id>.ico`，字节与包内那份相同；包换了才重写
- **AND** 包里没有 `icon.ico` 时窗口照样开、身份照样是应用那一个，只是不交图标，日志念一句回落

#### Scenario: SH-035 固定到任务栏的按钮点得开对的那个应用
- **WHEN** 看某应用窗口交给外壳的重启动作
- **THEN** 命令行是「"<可执行文件>" "<归档绝对路径>"」，两段都带引号；未打包直跑时在中间多一段 runtime 目录
- **AND** 重启显示名是清单里的应用名，与命令行成对交给外壳（只给一条时另一条也会被忽略）

### Requirement: 尺寸由清单定，位置与尺寸都不记
记窗口状态换来的是"下次开在同一个地方"，代价是清单值改了不生效、换块屏幕还会把窗口丢到屏外
（任务栏点得到、人看不见）。这个交换不值：尺寸由清单定（SH-015 与 `src/apps/specs/app-model.md` AP-012），
位置每次交给系统摆。

#### Scenario: SH-015 清单写了尺寸的应用，开出来就是那个尺寸
- **WHEN** 某应用清单写了 `defaultWidth: 980`、`defaultHeight: 660`
- **THEN** 开出来的窗口是 980×660，而不是 runtime 的默认 1100×740
- **AND** 只写 `defaultWidth: 1280` 的是 1280×740（高度跟 runtime），什么都不写的两个都跟 runtime

#### Scenario: SH-016 手动拖大的尺寸不留到下次
- **WHEN** 某应用清单写 `defaultWidth: 600`，用户上回把这窗口手动拉成 1125 宽
- **THEN** 下次打开仍是 600 宽：改清单值立刻生效，不用先删掉什么记忆

#### Scenario: SH-018 关掉再重开，位置由系统重新摆
- **WHEN** 把某应用窗口拖到屏幕一角、关掉，再指同一个包重开
- **THEN** 窗口由系统摆放，不回那个角：它的设置里不存在这个应用的窗口记录
- **AND** 整个 runtime 退出再启动也一样，没有"上次开在哪"这回事

#### Scenario: SH-019 应用可以把"正在看什么"交给标题栏中段
- **WHEN** 应用调 `window.setTitle('第一推动·畅销经典')`
- **THEN** 标题栏中段读得到那行字（过长被省略号收尾，不挤掉左右两端），任务栏那侧念「墨读 · 第一推动·畅销经典」
- **AND** 交 `null` 就收回：中段空着，任务栏恢复只念应用名

### Requirement: 应用窗口里 runtime 只添三样东西
标题栏、内容区的留白、主题变量。剩下的全是应用自己的事。

#### Scenario: SH-011 应用窗口的标题栏只念应用名
- **WHEN** 打开 vcp 的窗口
- **THEN** 标题栏左端只有应用名「vcp」与它自己的图标，读不到「飞船」这层前缀，也没有那个斜杠
- **AND** 标题栏上每颗键各有可读名称（主题 / 最小化 / 最大化或还原 / 关闭）

#### Scenario: SH-012 要不要留白由清单说了算
- **WHEN** 分别挂载 `flush: true` 与不写 flush 的应用
- **THEN** 前者内容区带 `app-window__body--flush`，runtime 不额外给内边距
- **AND** 后者由 runtime 给内边距与滚动

#### Scenario: SH-013 应用界面还在路上时读得到占位
- **WHEN** 应用自己的界面还没到位（它内部再切了一层懒加载）
- **THEN** 内容区读得到转圈占位，而不是一片空白

#### Scenario: SH-014 硬开一个没注册的应用，念的是主进程那一句
- **WHEN** 有人请求打开一个活动包表里没有的应用 id
- **THEN** 读得到「没有注册这个应用：<id>」，不出现 Electron 的内部措辞
- **AND** 这句由主进程说，渲染侧不再自己拼一套
