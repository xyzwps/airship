手把手做一个应用

走完这一页你会有：一扇自己的窗口、一份契约、三条用例、一个 hello.airship 包、一枚每用户安装器。全程只改自己那一个目录， runtime 侧一个文件都不用动。

下面每一条命令、每一段输出与每一句报错都是 2026-11-20 在本机（Windows，仓库 953901d）照着走出来的，照抄即可；走完示例已删干净， 所以这一页不留下第九个应用。只有 just dev 那一节给的是配方本身的行为（它常驻前台开着窗口，没法照抄输出），窗口那一屏用的是同一轮 just shot 的实拍判据。文档页讲为什么这样搭、规矩是什么，这一页只讲怎么一步步做。

先定三件事

动手之前把这三个数决定下来，后面改名很麻烦：

id
hello。它是目录名、包名前段、数据目录名，也是 airship://hello/index.html 里那一段。硬性形状：^[a-z][a-z0-9-]{0,31}$——小写字母开头，其后只用小写字母、数字与连字符，最长 32 位。
显示名
你好。写在清单的 name 里，中文、空格、标点都行；标题栏与任务栏念的都是它。
能力
这个应用要碰系统的哪几样。capabilities 是唯一授权面，没声明的一律拒绝；什么都不碰就写 []（生命游戏就是这么起的）。这一页的例子要"记住上次那句话"，所以是 ['settings']。

环境要 Windows、Node.js ^20.19.0 || >=22.12.0、just 与 Git Bash，然后 npm install。命令一律走 justfile，package.json 里没有 scripts，just 不带参数就列出全部配方。

这条配方自己就把 npm install（workspaces 要重新链）和产包跑完了，输出里那句"下一步"是给你看顺序的。npm 那两行 electron_mirror 的 warn 与这一轮无关，上面省了。

落下来的九份文件：

src/apps/hello/
  app.ts              纯数据清单：id / name / description / capabilities
  helloApp.tsx        组件本体
  hello.css           版心（配色一律用宿主给的 CSS 变量）
  index.html          入口文档，引 ./main.tsx；里面不写 CSP
  main.tsx            一行 createAirshipApp({ meta, component, icon })
  icon.svg            包根那一张图标：有且只有一张，不套底板
  package.json        @airship/hello，SDK 与 react 记在 devDependencies
  specs/hello.md      册子（占位，要重写）
  tests/hello.test.tsx 用例（占位，要重写）
范本没替你改的两处名字：脚本只替换大写的 CHANGE_ME 与中文"显示名"，所以复制出来组件还叫 ChangeMeApp、类名还叫 .change-me、main.tsx 里引的也还是那个名字。不影响跑，但第九个应用顶着一个"待替换"的名字不好看，顺手改掉。

第二步：第一次跑起来

just dev hello     # 直跑那一个应用：改一行代码即热更

开出来的窗口是范本的第一屏：标题栏念「你好」，右边那颗键是主题三档（每个应用各记各的），内容区念"现在亮的是暗色那一档"与"应用已经画出来了。"。

这一条路上有一处会让人困惑，值得先记住：

  • 清单与图标走包，文档走 dev server。runtime 注册的是命令行指来的 dist-apps/hello.airship，窗口标题、尺寸、能力那几样都从包里的 manifest.json 读。所以改了 app.ts 要重跑一次 just build-apps 才生效；只改组件源码不用。
  • 想看"与装好的 runtime 最接近的一条路"用 just start hello——文档也从包里加载（airship://hello/index.html），不起 dev server。

第三步：写功能

例子是一句话便签：打开时把上次记下的那句读回来，写一句新的点「记下」，输入是空的就不许顶掉存着的那句。功能定成这样，册子里要写的三条判据也就跟着出来了——先想清楚判据再动手，是这套规矩的起点。

清单里把话说完（其余字段留默认：窗口 1100×740，内容区留白由 runtime 给）：

// src/apps/hello/app.ts
import type { AppMeta } from '@airship/contract'

export const app: AppMeta = {
  id: 'hello',
  name: '你好',
  description: '记一句话，下次打开还在',
  capabilities: ['settings']
}

组件本体。api 由宿主作为 prop 递进来，应用侧除了 main.tsx 那一行不需要知道 runtime 的存在：

// src/apps/hello/helloApp.tsx
import { useEffect, useState, type JSX } from 'react'
import type { AppApi } from '@airship/contract'
import './hello.css'

/** 存的那一句话用哪个键：一个应用一份设置文件，键在同一份文件里别撞车 */
const KEY = 'note'

export default function HelloApp({ api }: { api: AppApi }): JSX.Element {
  const [note, setNote] = useState('')
  const [draft, setDraft] = useState('')
  const [hint, setHint] = useState('')
  const [error, setError] = useState('')
  const [ready, setReady] = useState(false)

  useEffect(() => {
    void api.settings
      .get<string>(KEY, '')
      .then(
        (saved) => setNote(saved),
        // 没声明能力时这里收到的就是契约层那句中文，不是 Electron 的内部措辞
        (err: unknown) => setError(err instanceof Error ? err.message : String(err))
      )
      .then(() => setReady(true))
  }, [api])

  async function save(): Promise<void> {
    const text = draft.trim()
    if (text === '') {
      setHint('先写点什么')
      return
    }
    try {
      await api.settings.set(KEY, text)
      setNote(text)
      setDraft('')
      setHint('')
      setError('')
    } catch (err: unknown) {
      setError(err instanceof Error ? err.message : String(err))
    }
  }

  return (
    <div className="hello">
      <h2>你好</h2>
      {!ready && <p className="hint">正在读上次记下的那句…</p>}
      {ready && error === '' && <p className="hello-note">{note === '' ? '还没记下过什么。' : note}</p>}
      <input id="hello-draft" className="input" placeholder="要记下的那句话"
        value={draft} onChange={(e) => setDraft(e.target.value)} />
      <div className="row">
        <button className="btn btn--primary" type="button" onClick={() => void save()}>记下</button>
        {hint !== '' && <span className="hint">{hint}</span>}
      </div>
      {error !== '' && <p className="error">{error}</p>}
    </div>
  )
}

样式只补一处，其余交给宿主：.btn / .btn--primary / .input / .hint / .error 这些类名与 var(--fg)、var(--bg-elev)、var(--border) 那一族变量都是 SDK 给的（src/sdk/styles/airship.css）， 自己另调一套配色就会跟标题栏那颗主题键打架。 

/* src/apps/hello/hello.css */
.hello { display: flex; flex-direction: column; gap: 12px; max-width: 560px; }
.hello h2 { margin: 0; font-size: 20px; color: var(--fg); }
.hello-note {
  margin: 0; padding: 14px 16px; border: 1px solid var(--border); border-radius: 10px;
  background: var(--bg-elev); color: var(--fg); font-size: 17px; min-height: 24px;
}

第四步：写册子

功能写之前先把它落成契约。四档结构是硬的：## Purpose → ### Requirement → #### Scenario → WHEN/THEN，一条 Scenario ≤ 5 行、只锁一个不变量，只写用户看得见的那件事。 

<!-- src/apps/hello/specs/hello.md -->
# hello

## Purpose
一句话便签：界面上只有"上次记下的那句"与"写一句新的"两件事。一本册子只管这一块。

### Requirement: 那句话存在应用自己的设置里
依据：设置按应用分命名空间（docs/architecture.md 的数据与存储一节），重启读得回来才算记住。

#### Scenario: HE-001 第一次打开还没有任何东西可记
- **WHEN** 打开这个应用，设置里没有过那句话
- **THEN** 界面上读得到「还没记下过什么。」

#### Scenario: HE-002 写下并记下之后，重开还是那一句
- **WHEN** 在「要记下的那句话」里写「买咖啡豆」，点「记下」，再重开一次
- **THEN** 界面上读得到「买咖啡豆」，不再念「还没记下过什么。」
- **AND** 输入框清空，等着写下一句

### Requirement: 空的那一句不该顶掉记下的那句
依据：点了「记下」却没改动任何东西，用户要看得见为什么。

#### Scenario: HE-003 输入是空的，界面念「先写点什么」
- **WHEN** 什么都不写，直接点「记下」
- **THEN** 界面上读得到「先写点什么」
- **AND** 上次记下的那句还是那句
编号必须是大写两三个字母加三位号。范本里那句 CHANGE_ME-001 复制出来会变成 hello-001，而扫描器认的是 [A-Z]{2,3}-\d{3}——小写号它一条都看不见，于是这本册子被判"空的"。前缀去 docs/specs/index.md 的索引表里挑一个没被占用的（这一页挑了 HE），编号一旦提交不复用、不重排。

第五步：写用例

用例是册子的影子：标题以同一个编号开头，判据就是册子里那句可观察的话。替身 FakeAirship 与挂载器 mountUi 住在 @airship/sdk/testing，能力闸门与拒绝措辞都取契约层真源，所以"没声明 settings 时用户看见的那句中文"在测试里和在真 runtime 里是同一句。 

// @vitest-environment jsdom
// src/apps/hello/tests/hello.test.tsx
import { describe, expect, it } from 'vitest'
import { FakeAirship, mountUi } from '@airship/sdk/testing'
import HelloApp from '../helloApp.tsx'
import { app } from '../app.ts'

function fresh() {
  const fake = new FakeAirship({ id: app.id, capabilities: app.capabilities })
  fake.settingsStore['note'] = '买咖啡豆'
  return fake
}

describe('一句话便签', () => {
  it('HE-001 第一次打开还没有任何东西可记', async () => {
    const fake = new FakeAirship({ id: app.id, capabilities: app.capabilities })
    const m = await mountUi(<HelloApp api={fake.api} />, { fake })
    await m.settle()

    expect(m.text()).toContain('还没记下过什么。')
    expect(m.text()).not.toContain('Error invoking remote method')
    m.unmount()
  })

  it('HE-002 写下并记下之后，重开还是那一句', async () => {
    const fake = new FakeAirship({ id: app.id, capabilities: app.capabilities })
    const m = await mountUi(<HelloApp api={fake.api} />, { fake })
    await m.settle()

    await m.type('要记下的那句话', '把船票取出来')
    await m.press('记下')
    expect(fake.settingsStore['note']).toBe('把船票取出来')
    m.unmount()

    // 同一份设置再挂一次，就是"重开"
    const again = await mountUi(<HelloApp api={fake.api} />, { fake })
    await again.settle()
    expect(again.text()).toContain('把船票取出来')
    expect(again.has('还没记下过什么。')).toBe(false)
    again.unmount()
  })

  it('HE-003 输入是空的，界面念「先写点什么」', async () => {
    const fake = fresh()
    const m = await mountUi(<HelloApp api={fake.api} />, { fake })
    await m.settle()

    await m.press('记下')
    expect(m.text()).toContain('先写点什么')
    expect(m.text()).toContain('买咖啡豆')
    expect(fake.settingsStore['note']).toBe('买咖啡豆')
    m.unmount()
  })
})

挂载器故意不引第三方测试库：m.text() 拿整棵树的可见文字，m.press('记下') 按可见文字找按钮，m.type(placeholder, 值) 往输入框里写字，settle() 把读设置那条异步链跑干净。判据写成"用户看得见的话"，界面措辞一改只红那一行。

第六步：第一轮 just check 会红，红得对

上面这些照抄下去跑 just check（= 类型 + 单测 + 册子差集），第一次会红三条。这三条正是这套规矩在替你把关，原文照抄： 

× AP-011 应用用到的每个契约域，清单里都声明过
  AssertionError: hello 用了 api.settings 却没声明 settings

× 索引表登记的册子与实际存在的册子一一对应
  AssertionError: 磁盘上有但索引没登记: expected [ 'hello' ] to deeply equal []

× HE-001 第一次打开还没有任何东西可记
  AssertionError: expected '你好记下hello 没有声明 settings 能力（要用它就在 apps…' to contain '还没记下过什么。'
  Expected: "还没记下过什么。"
  Received: "你好记下hello 没有声明 settings 能力（要用它就在 apps/hello/app.ts 的 capabilities 里声明）"
  • 第一条：app.ts 里补 capabilities: ['settings']。第三条跟着一起好——界面读到的那句中文（hello 没有声明 settings 能力…）来自 src/shared/contract/errors.ts，措辞只有一份，产品与替身念同一句。
  • 第二条：在 docs/specs/index.md 的应用表里加一行——前缀 HE、这块管什么、册子文件名 hello.md、验证档 自动化。索引表是册子的名单，漏登记等于这本册子没归过档。
  • 补完能力还会再红一次：hello 用了 api.proc 却没声明 proc。这条红是范本自己的注释造成的——app.ts 的注释里原话写着 api.proc.，而扫描器按文本找调用点，注释也算。把那句注释改成不带尾点的写法（"用了 api.settings 与 api.proc 这些域"）就干净了。

第八步：出包与安装器

包已经在了：dist-apps/hello.airship——一个 zip 归档换了扩展名，里面是 manifest.json + index.html + icon.svg + assets/，88 KB（归档内 227 KB）。给别人用的话产它自己的安装器： 

$ just app-installer hello
node code/build-apps.mjs hello
产 1 个包 → C:\Users\xyzwp\Develop\airship\dist-apps
  hello       88 KB（归档内 227 KB）→ hello.airship
node code/make-app-installer.mjs hello
已产安装器 release/apps/hello-Setup-0.1.0.exe
SHA256 <64 位十六进制>   # 同名 .sha256 落在旁边；每次构建的哈希不一样
  • 安装器是每用户的（RequestExecutionLevel user，不要管理员），装进 %LOCALAPPDATA%\airship\apps\hello\，桌面与开始菜单各留一枚快捷方式，图标由包内那张 SVG 经 resvg 出 PNG 再转多尺寸 .ico。
  • 授权在安装期一次完成：装之前念一遍能力清单（这一页的例子念"存自己的设置"），点过确定之后双击快捷方式直接开窗口，运行期不再弹确认卡片。
  • 版本号读 src/apps/hello/package.json，各应用独立演化，不跟 runtime 跳。没有代码签名，第一次运行会被 SmartScreen 拦一道。

报错对照表

这一页实走时真撞上的几条，原文照录：

念出来的话为什么怎么办
id "hello_x" 不合形状：只能是 1 到 32 位，小写字母开头… 产包期契约层拒清单。code/new-app.mjs 自己那道判据是从契约文件里抠正则的，抠的时候把结尾的 $ 一起削掉了，所以带尾缀的坏 id 会先建目录、再跑 npm install，到产包才喊。 删掉 src/apps/<坏 id> 目录，用合规 id 重来；见下一条为什么必须删干净。
工装包注册失败 hello_x.airship：… id "hello_x" 不合形状…，而且 Test Files 45 failed、每个文件 (0 test) 用例开局要把仓库里每份真清单铺进活动包表，一份不合格的清单把整套测试拖死——症状是全红而不是红一条。 看见 (0 test) 先怀疑 src/apps/ 下多了一个目录，删掉再跑 just check。
这些应用不存在或不完整：hello（在 src/apps 里有的：albedo, books, …） 名单判据是"四件齐全"：app.ts + index.html + main.tsx + 一张 icon.{svg,png,jpg,jpeg,webp}。少一张图标，目录就从名单上消失了，措辞不会指名缺哪件。 补齐缺的那件（图标有且只有一张）。名字里出现"或不完整"就是这个意思。
src/apps/hello/specs/hello.md：一条 Scenario 都没有，这本册子是空的 编号形状不对（hello-001 小写），扫描器看不见任何一条。 换成 HE-001 这种大写前缀 + 三位号，用例标题跟着改。
磁盘上有但索引没登记: expected [ 'hello' ] … 新册子没进 docs/specs/index.md 的表。 加一行：前缀、这块管什么、册子文件名、验证档。
hello 用了 api.proc 却没声明 proc（你根本没调用它） AP-011 按文本找 api.<域>. 的调用点，注释与字符串里的字样也算——范本 app.ts 的注释就带着 api.proc.。 把注释里那两个字样写成不带尾点的形式；别为了消红去声明用不到的能力，能力清单是要念给用户听的。
src/apps/hello 已经存在——换 id 或先把它删掉 复制前先判目录存在。注意 Windows 文件系统不分大小写：just new-app Hello 也会被这一条挡掉，而不是报"id 不合形状"。 换 id。

收尾检查单

  1. 能观察的三条都齐

    just check 绿（类型 + 单测 + 双向差集）；just shot 里你自己那一屏观感过眼；要真环境的那条另跑 just e2e / just wsld-real。

  2. 包与安装器产得出来

    just app-installer hello 出 release/apps/hello-Setup-<版本>.exe 与同名 .sha256。

  3. 没越界

    没有 import 指向 src/runtime/** 或 @airship/runtime（AP-013）；入口 html 里 src/href 全是相对路径，引用不越出包；CSP 不在自己 html 里写（AP-014）；说明符写包名而不是手写别名。

  4. 清单只写自己的事实

    id / name / description / capabilities / platforms / tools / sharedNamespaces / flush / defaultWidth / defaultHeight。被驳回过的字段别加回来：iconPath、order、窗口状态的记忆。
