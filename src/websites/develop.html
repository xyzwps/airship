开发你的第一个应用

准备环境

  • 安装 airship runtime：airship-runtime-Setup-<版本>-x64.exe，下载地址：（留空，待定）。
  • 安装 Node.js：>= 24。

我们的目标

开发一个简单的 todo 应用。它包含一个页面，可以在里面管理你自己的 todo。

第一步 · 创建一个最小应用

应用 id 就是项目 package.json 的 name——手脚架把它落成目录名（小写字母开头，小写字母、数字与连字符，最长 32 位）。 后面每条命令都不带 id，认的就是它。 

$ npx create-airship-app my-todo
已建 minimal 项目：C:\Users\…\Temp\my-todo

下一步（都在 my-todo 里跑）：
  npm install       装上 @airship/sdk、@airship/cli 与 react/vite
  npm run dev       开发模式起窗——改 src 下的源码，窗口里刷新即见
  npm run start     直跑构建好的产物，与装好后双击快捷方式同一条路
  npm run pack      产 dist-apps/my-todo.airship
  npm run installer 产每用户安装器（这台机器要先有 NSIS：winget install nsis.nsis）

落下来的项目一共十一个文件，起点就带一份随包后台：

my-todo/
  package.json          name 就是应用 id，version 就是安装器的版本号
  README.md
  .gitignore
  src/
    app.ts              纯数据清单：id / name / description / capabilities
    App.tsx             组件本体，宿主把 api 当 prop 递进来
    app.css             版心：配色只用宿主给的 CSS 变量
    backend.ts          随包后台的入口：这份文件在，包根就有 backend.js（约定）
    index.html          入口文档，引 ./main.tsx；里面不写 CSP
    main.tsx            一行 createAirshipApp({ meta, component, icon })
    icon.png            包根那张源图：只认 png，不套底板
    icon.ico            外壳图标：自己备一张多尺寸的（见第四步）

装上依赖，产第一个包

$ npm install

开头那两行 > my-todo@0.1.0 pack / > airship pack 是 npm 在念 package.json 的 scripts—— npm run xx 跑的就是 airship 那四个动词，后面各段为省地方不再重复这两行回显。

my-todo.airship 就是 zip 归档换了扩展名；manifest.json 不是手写的，是 app.ts 那份纯数据的投影——改清单永远改 app.ts。

开出来的一屏：标题栏念「my-todo」，正文一句档位提示、一句「按了 0 次。」与一颗「点我」。 这个 0 不是前端自存的——开窗时页面 invoke('get') 从后端进程取现值，点一下是一次 inc 请求-回话，日志里那三条后端行就是这么来的。 之后双击快捷方式跑装好的应用，走的就是这同一条路。

这一屏要装好的 runtime 带 backend 通道。停在更早版本的机器上，界面会念「后端程序中途退出，没等到 get 的回话（下一次调用会再拉起一个新的）」——装最新安装包即可，不是包坏了。

读一读这个起点

清单只写这个应用自己的事实——被驳回过的字段（iconPath、order）不在里面，后台也不在这里：

// src/app.ts（手脚架起点）
import type { AppMeta } from '@airship/contract'

export const app: AppMeta = {
  id: 'my-todo',
  name: 'my-todo',
  description: '一句话说清这个应用是干什么的',
  capabilities: []        // 唯一授权面，用不到就写空数组；后台不在这行里（见下）
}

入口脚本把清单与组件交给 SDK 宿主，这是应用侧唯一知道"外面有个 runtime"的地方：

// src/main.tsx
import { createAirshipApp } from '@airship/sdk'
import { app } from './app.ts'
import App from './App.tsx'

createAirshipApp({ meta: app, component: App, icon: './icon.png' })

组件就是普通 React。两条纪律：配色只用 var(--fg)、var(--bg-elev) 这一族宿主 CSS 变量，别写死颜色（否则与标题栏那颗主题键打架）； 想碰系统就经 api. 的对应域，并回 app.ts 把那个能力声明上——没声明的一律拒绝，且拒绝时界面收到的是一句中文人话。

那颗计数器的数字住在 src/backend.ts 的内存里。整份文件就这么长——启动后第一件事报就绪，来一条 { seq, method } 回一条 { seq, ok, value }： 

// src/backend.ts
/**
 * my-todo 的后端：随包自带、由 runtime 起成它自己的一份进程。
 *
 * 有它靠的是约定，不是清单：这个文件由产包流水编成包根那份 `backend.js`，
 * runtime 在包里看到那个条目才起进程。删掉这个文件，应用就没有后台。
 *
 * 线与规矩（契约见 airship 文档的 backend 一节）：
 *   - 启动后**第一件事**发 `{ ready: true }`，runtime 才把调用喂进来；
 *   - runtime 发来 `{ seq, method, payload }`，回 `{ seq, ok: true, value }` 或 `{ seq, ok: false, error }`；
 *   - 这个计数住在内存里：窗口一关进程就收掉，数字归零。
 *     要跨重启留住数字，写 `AIRSHIP_DATA_DIR`——todo 模板的 backend.ts 就是那么办的。
 */

/** runtime（utilityProcess）给的消息端口——Electron 那份类型不在模板依赖里，这里自己声明够用的形状 */
interface ParentPort {
  on(event: 'message', handler: (ev: { data?: { seq?: number; method?: string } }) => void): void
  postMessage(message: unknown): void
}

const parent = (process as unknown as { parentPort: ParentPort }).parentPort

/** 计数：这个应用唯一的数字，它在这里——前端不自存一份，每次读的都是进程里这一个 */
let count = 0

const handlers: Record<string, () => unknown> = {
  get: () => count,
  inc: () => ++count
}

parent.on('message', (event) => {
  const { seq, method } = event.data ?? {}
  try {
    const handler = method ? handlers[method] : undefined
    if (!handler) throw new Error(`后端不认的方法：${method}`)
    parent.postMessage({ seq, ok: true, value: handler() })
  } catch (e) {
    // 回给前端的 error 就是要念给用户听的人话——别回堆栈
    parent.postMessage({ seq, ok: false, error: e instanceof Error ? e.message : String(e) })
  }
})

parent.postMessage({ ready: true })

第二步 · 编写应用代码

起点的计数住在后端内存里，窗口一关就归零。把它升级成待办清单，动的还是那三份文件：App.tsx 与 app.css 换成待办界面、backend.ts 从内存计数改成写磁盘 JSON——清单不为后台加一行。 airship 里"有没有后端"是包形状的事实，不是授权：应用目录里有这份文件，产包流水就把它编成包根那份 backend.js；runtime 在包里看到那个条目， 才把它起成它自己的一份进程（Electron utilityProcess），前后端走消息做请求-回话；它崩了不拖累窗口，窗口关掉它也退出。（npx create-airship-app <目录> --template todo 就是这三份文件的成品版，拿来对照最方便。）

界面上加一条待办，它就落进 %APPDATA%\airship\apps\my-todo\data\todos.json——每个应用独享 data 目录（后端进程里就是 AIRSHIP_DATA_DIR），别的应用碰不到，卸载也不跟着删。

后端靠约定，不进清单

清单只把显示名和描述换成待办那两行，能力位照旧空数组：能力位收的是宿主代管的资源（读写设置、开文件…），"随包自带一段 Node 代码"是这个包自己的构成物——从起点到待办，它都不占能力位、也不写进清单。

// src/app.ts
import type { AppMeta } from '@airship/contract'

export const app: AppMeta = {
  id: 'my-todo',
  name: '待办清单',
  description: '数据由随包自带的后端写进磁盘 JSON 的待办清单',
  capabilities: []        // 后台不在这行里——src/backend.ts 在，就有后台（约定）
}

后端程序

普通 TypeScript 模块，没有框架。把起点那份内存计数整份换成模板里这份（注释是自带的），逐字贴进 src/backend.ts 就能跑：

// src/backend.ts
/**
 * 待办清单 的后端：随包自带、由 runtime 起成它自己的一份进程。
 *
 * 有它靠的是约定，不是清单：这个文件由产包流水编成包根那份 `backend.js`，
 * runtime 在包里看到那个条目才起进程。删掉这个文件，应用就没有后台。
 * 复杂应用在这份文件之下自己组织目录——import 都会被编进同一条文件。
 *
 * 线与规矩（契约见 airship 文档的 backend 一节）：
 *   - 启动后**第一件事**发 `{ ready: true }`，runtime 才把调用喂进来；
 *   - runtime 发来 `{ seq, method, payload }`，回 `{ seq, ok: true, value }` 或 `{ seq, ok: false, error }`；
 *   - 数据目录从 `AIRSHIP_DATA_DIR` 拿——只有这个应用那一族碰得到，卸载也不跟着删。
 *
 * 它崩了不拖累窗口：在途的调用会听到「后端程序中途退出」，下一次调用拉起新的进程。
 */

import { existsSync, mkdirSync, readFileSync, writeFileSync } from 'node:fs'
import { join } from 'node:path'

interface Item {
  id: number
  text: string
  done: boolean
}

/** runtime（utilityProcess）给的消息端口——Electron 那份类型不在模板依赖里，这里自己声明够用的形状 */
interface ParentPort {
  on(event: 'message', handler: (ev: { data?: { seq?: number; method?: string; payload?: { text?: string; id?: number } } }) => void): void
  postMessage(message: unknown): void
}

const parent = (process as unknown as { parentPort: ParentPort }).parentPort
const FILE = join(process.env.AIRSHIP_DATA_DIR ?? '.', 'todos.json')

function load(): Item[] {
  if (!existsSync(FILE)) return []
  return JSON.parse(readFileSync(FILE, 'utf8')) as Item[]
}

function save(items: Item[]): void {
  mkdirSync(join(FILE, '..'), { recursive: true })
  writeFileSync(FILE, `${JSON.stringify(items, null, 2)}\n`, 'utf8')
}

const handlers: Record<string, (payload?: { text?: string; id?: number }) => unknown> = {
  list: () => load(),
  add: (payload) => {
    const text = String(payload?.text ?? '').trim()
    if (text === '') throw new Error('不能加一条空待办')
    const items = load()
    const item: Item = { id: items.reduce((max, t) => Math.max(max, t.id), 0) + 1, text, done: false }
    items.push(item)
    save(items)
    return item
  },
  toggle: (payload) => {
    const items = load()
    const item = items.find((t) => t.id === payload?.id)
    if (!item) throw new Error('没有这条待办')
    item.done = !item.done
    save(items)
    return item
  },
  remove: (payload) => {
    const items = load()
    const kept = items.filter((t) => t.id !== payload?.id)
    if (kept.length === items.length) throw new Error('没有这条待办')
    save(kept)
    return kept
  }
}

parent.on('message', (event) => {
  const { seq, method, payload } = event.data ?? {}
  try {
    const handler = method ? handlers[method] : undefined
    if (!handler) throw new Error(`后端不认的方法：${method}`)
    parent.postMessage({ seq, ok: true, value: handler(payload) })
  } catch (e) {
    // 回给前端的 error 就是要念给用户听的人话——别回堆栈
    parent.postMessage({ seq, ok: false, error: e instanceof Error ? e.message : String(e) })
  }
})

parent.postMessage({ ready: true })

消息一览：

方向那一行消息什么时候
runtime → 后端{ seq, method, payload }前端每次 invoke 一条
后端 → runtime{ ready: true }启动后第一件事，10 秒内必须发
后端 → runtime{ seq, ok: true, value } / { seq, ok: false, error }对上一条的回话
后端 → runtime{ event: true, method, payload }后端主动推给界面（不需要人问）

环境变量：AIRSHIP_APP_ID、AIRSHIP_DATA_DIR、AIRSHIP_CACHE_DIR。后端要 npm 依赖就写在应用的 package.json 里，随包带着走。

前端怎么调

前端只渲染状态、只发调用，不碰磁盘。一次 invoke 就是一次请求-回话：await 到的就是 handler 的返回值，后端回的 ok: false 原样 reject 成那句人话。整份 src/App.tsx： 

// src/App.tsx
import { useEffect, useState, type JSX } from 'react'
import type { AppApi } from '@airship/contract'
import './app.css'

type Item = { id: number; text: string; done: boolean }

/** 把 invoke 的失败收成那句人话：后端回的 error 原样就是给用户的 */
function reasonOf(e: unknown): string {
  return e instanceof Error ? e.message : String(e)
}

/**
 * 前端这一半：只渲染状态、只发调用，不碰磁盘。
 *
 * 每一次 `api.backend.invoke(method, payload)` 是一次请求-回话：
 * await 到的就是后端 handler 的返回值；后端回的失败会原样 reject 成那句人话。
 */
export default function App({ api }: { api: AppApi }): JSX.Element {
  const [items, setItems] = useState<Item[]>([])
  const [text, setText] = useState('')
  const [error, setError] = useState<string | null>(null)

  async function refresh() {
    try {
      setItems(await api.backend.invoke<Item[]>('list'))
      setError(null)
    } catch (e) {
      setError(reasonOf(e))
    }
  }

  useEffect(() => {
    void refresh()
  }, [])

  async function add() {
    const t = text.trim()
    if (t === '') return
    try {
      await api.backend.invoke('add', { text: t })
      setText('')
      await refresh()
    } catch (e) {
      setError(reasonOf(e))
    }
  }

  async function toggle(id: number) {
    try {
      const item = await api.backend.invoke<Item>('toggle', { id })
      setItems((old) => old.map((t) => (t.id === item.id ? item : t)))
      setError(null)
    } catch (e) {
      setError(reasonOf(e))
    }
  }

  async function remove(id: number) {
    try {
      await api.backend.invoke('remove', { id })
      setItems((old) => old.filter((t) => t.id !== id))
      setError(null)
    } catch (e) {
      setError(reasonOf(e))
    }
  }

  return (
    <div className="app">
      <h2>待办清单</h2>
      <form
        className="add"
        onSubmit={(e) => {
          e.preventDefault()
          void add()
        }}
      >
        <input
          value={text}
          placeholder="想做点什么？"
          onChange={(e) => setText(e.target.value)}
        />
        <button type="submit">加上</button>
      </form>
      {error && <p className="error">{error}</p>}
      <ul className="list">
        {items.map((item) => (
          <li key={item.id} className={item.done ? 'done' : ''}>
            <label>
              <input type="checkbox" checked={item.done} onChange={() => void toggle(item.id)} />
              <span>{item.text}</span>
            </label>
            <button type="button" className="del" onClick={() => void remove(item.id)}>
              删掉
            </button>
          </li>
        ))}
        {items.length === 0 && <li className="empty">还没有待办，加一条。</li>}
      </ul>
    </div>
  )
}

第三步 · 以开发模式运行程序

$ npm run dev
[airship] 构建 my-todo 的包（注册期只读清单与图标）
[airship] dev server http://127.0.0.1:5177 —— 改 C:\Users\…\my-todo\src 下的源码，窗口里刷新即见
[airship] runtime C:\Program Files\airship\runtime\airship.exe（窗口数据在 .airship-dev/my-todo，不碰日常那套 userData）

这条路上同时有 dev server、被拉起的 runtime、一扇加载 dev server 源码的窗口。终端别急着关——它退出时窗口与 dev server 一起收，留着就是为了看报错。 窗口数据在项目里的 .airship-dev/my-todo，不抢日常那套 userData 的单实例锁。

哪样走包、哪样走源码

  • 前端源码走 dev server：改 App.tsx、app.css 刷新即见，不用重新产包。
  • 清单、图标与后端走包：窗口标题、尺寸与能力都是 app.ts 的投影，后端进程跑的也是包里那份 backend.js——产包流水把 src/backend.ts 现编出来的就是它。 所以改了 app.ts 或 src/backend.ts 要重跑 dev（它开局重新产一次包），只刷新界面没用。
  • dev 的端口默认 5177 且不许静默换端口：同时开两个应用的 dev，给第二个 npm run dev -- --port 5178（-- 之后的参数 npm 原样交给脚本）。

直跑与装好后同路

想看"和装好后一模一样"的那条路用 npm run start：文档从包里加载（airship://<id>/index.html），不起 dev server。 第一步那三条后端日志就是这条路跑出来的——后端进程随窗口退出而退出，内存里的计数归零；要留住的是写进 AIRSHIP_DATA_DIR 的东西。

第四步 · 发布！

产安装器要这台机器有 NSIS（产包和 dev 都不需要）。没装的话第一条命令会把话说到脸上：

$ npm run installer
找不到 makensis：装一份 NSIS（例如 winget install nsis.nsis —— 或让 AI 装：「帮我安装 NSIS 并让 makensis 进 PATH」），
或用 --makensis <路径> / 环境变量 AIRSHIP_MAKENSIS 指到它。

三条路：winget install nsis.nsis（或让 AI 装）、设 AIRSHIP_MAKENSIS、每次给 --makensis。指到机器上已有的那份也行：

$ npm run installer -- --makensis "C:\Users\xyzwp\AppData\Local\tauri\NSIS\makensis.exe"
已产安装器 C:\Users\…\my-todo\release\apps\my-todo-Setup-0.1.0.exe
SHA256 26bf86dab56782fcf170c4c25286b30fe2fe2b417caae3045b3917b05cb701f9
安装器就绪：C:\Users\…\release\apps\my-todo-Setup-0.1.0.exe（分发给别人前注意：第一次运行会被 SmartScreen 拦一道——没有代码签名）

icon.ico 由你自备

任务栏与快捷方式那颗外壳图标只认磁盘上的 .ico——runtime 不会现场转格式。模板各带一张占位 icon.ico，发版前换成你自己的多尺寸 .ico（16 / 32 / 48 / 256 齐）。源图只认那张 icon.png（svg / jpg / webp 那批 2026-11-26 起退场，留着产包会点名拒绝），.ico 不算源图、与它同放包根是正常形状。缺了它，产包响亮失败： 

包根没有 icon.ico：任务栏与快捷方式那颗外壳图标只认磁盘上的 .ico

安装器都干了什么

  • 每用户，不要管理员：装进 %LOCALAPPDATA%\airship\apps\my-todo\，桌面与开始菜单各一枚快捷方式（目标是 runtime 的 airship.exe + 包路径）。 它先找 runtime，找不到就中止念出来——装应用不重新送 runtime。
  • 授权在安装期一次完成：安装页念契约层那份能力清单；归档根带 backend.js 的，末尾多念一句「跑它自带的后台程序」——这句从包形状读，不占能力位。装完双击直接开窗口，运行期不再弹确认卡片。
  • 版本号读项目根 package.json 的 version（要盖一次给 --version）；.exe 旁落同名 .sha256；旧包先删再产——宁可报错没有，不许旧包冒充新包。
  • 没有代码签名，SmartScreen 会拦第一次。

分发出去之后

收到 my-todo-Setup-0.1.0.exe 的人只需装过 runtime。他的数据在 %APPDATA%\airship\apps\my-todo\data\todos.json，卸载应用不删它，重装回来待办还在。

报错对照表

本轮实走撞出的，原文照录：

念出来的话为什么怎么办
这个包跑不起来：<文件名>，下面逐条「哪个归档：为什么」 注册判据不合格的统一报法（缺清单、坏 JSON、引用越出包…都从这句出）。 逐条原因就写在下面，照着改清单或产物；改完重跑 pack。
找不到 makensis：装一份 NSIS（例如 winget install nsis.nsis …） 这台机器没有 NSIS（产包不需要，只有安装器需要）。 三条路见第四步：winget 装、AIRSHIP_MAKENSIS、--makensis。
包根没有 icon.ico：任务栏与快捷方式那颗外壳图标只认磁盘上的 .ico 产包期查（外部作者的包不会替你现转格式）。 应用目录放一张多尺寸 icon.ico 再产包；.ico 是产物，不算第二张图标。
后端入口只能有一份：backend.ts 与 backend.js 都在——留一个，复杂应用的目录归这个文件自己组织 src/ 下同时放了两份后端入口，产包流水不知道该编哪一份——有它靠约定，约定只认一处。 留一份（模板那份叫 backend.ts），删掉另一份再产包。
后端程序中途退出，没等到 <method> 的回话（下一次调用会再拉起一个新的） 后端进程在回话之前没了：自己崩了，或装好的 runtime 还停在带 backend 通道之前的版本。 先看 backend.ts 有没有在报就绪之前抛；runtime 旧就装最新安装包。
airship pack 不接 id：id 念的是项目 package.json 的 name，把 "my-todo" 去掉就行 四个动词都不接 id——id 的唯一真源是项目根 package.json 的 name。 命令行去掉 id，直接 npm run pack。
没有 C:\…\package.json：airship 命令要在应用项目的根目录跑 命令在项目根之外跑，找不到那份 package.json。 cd 进项目根再跑。
app.ts 的 id "other-todo" 与 package.json 的 name "my-todo" 不一致：id 只有一个真源，改齐再产包 产包期两处对照——id 写进了两份文件，只许一处说了算。 把 app.ts 的 id 改成与根 package.json 的 name 相等。
没有 C:\…\dist-apps\my-todo.airship：先跑 airship pack 安装器吃的是已产好的包，包还没产。 先 npm run pack，再 npm run installer。
目录名 "My_Todo" 当不了应用 id：只能是 1 到 32 位，小写字母开头，其后只用小写字母、数字与连字符。 目录名就是 id，产包、注册、数据目录同用这一个名字。 换个目录名重来。
C:\…\my-todo 已经存在且不是空目录，手脚架不往里盖东西 防止盖掉你已有的改动。 换目录名，或先把那个目录清空。
