# shell

## Purpose
窗口与启动器：壳自己那一屏画什么、一个应用一个窗口的规矩、窗口状态各记各的。
每个应用在自己窗口里做什么不在这里（见 `src/apps/vcp/specs/vcp.md`、`src/apps/books/specs/books.md` 等），
标题栏与主题的呈现见 `theme.md`；跨进程调用的规矩见 `bridge.md`。

> 只能在真机上观察的期望（单实例锁、一个应用崩了不带崩别人）记在
> [架构](../../../docs/architecture.md) §3，不在这本册子里充数。

### Requirement: 启动器就是一张应用格子
格子里只有图标与名字。说明文字、能力标签、壳状态一概不放——要看的东西在应用自己里看。

#### Scenario: SH-001 格子里读得到图标与名字，读不到说明文字
- **WHEN** 打开启动器
- **THEN** 每个已注册应用一格，格子里读得到应用名，图标是一张 `icon.*` 文件
- **AND** 格子里读不到清单里的 `description`，也读不到能力名（`fs.read`、`proc` 这类字样一个都不出现）

#### Scenario: SH-002 点一格，把这一个应用的 id 交给壳去开窗口
- **WHEN** 点「vcp」那一格
- **THEN** 壳收到一条"打开 vcp"的请求，参数就是 vcp 的 id
- **AND** 界面不自己加载应用组件，也不把别的应用一起拉起来

#### Scenario: SH-003 当前平台用不了的应用不进格子
- **WHEN** 在 macos 上打开启动器，而某个应用的清单写着 `platforms: ['windows']`
- **THEN** 那一格不出现，其余应用照常列出
- **AND** 清单里没写 `platforms` 的应用在任何平台都进格子

#### Scenario: SH-004 硬开一个用不了的应用，读得到为什么被拒
- **WHEN** 有人绕过格子直接请求打开那个只支持 windows 的应用，壳拒绝了
- **THEN** 启动器上出现一行原因，读得到「在这台机器上用不了」与「它只在 windows 上可用，这台机器是 macos」
- **AND** 不出现 Electron 的内部措辞（`Error invoking remote method` 一句都不要）

### Requirement: 一个应用一个窗口，窗口之间各过各的
窗口是隔离单位：同一个应用只开一个，关窗要把它名下的摊子收干净。

#### Scenario: SH-005 同一个应用再点一次，是聚焦而不是再开一个
- **WHEN** vcp 的窗口已经活着，又请求打开 vcp
- **THEN** 台账给出的动作是"聚焦已有窗口"，活着的 vcp 窗口始终只有一个
- **AND** 另一个应用（PDF）的窗口存在与否不影响这个判定

#### Scenario: SH-006 关掉应用窗口，它名下的子进程跟着收掉
- **WHEN** 一个应用在跑一条真命令（子进程还活着），把它的窗口关掉
- **THEN** 该应用名下在跑的任务被逐个终止，返回被终止的条数
- **AND** 别的应用名下的任务一条都不被碰

#### Scenario: SH-007 窗口没了，归属随之解除
- **WHEN** 某应用的窗口关闭
- **THEN** 它的 webContents 不再认得出归属（`ownerOfContents` 返回空）
- **AND** 台账里它不再算"开着的应用"，可以再开一个新窗口

#### Scenario: SH-008 窗口状态一应用记一份
- **WHEN** vcp 窗口拖成 1200×800，PDF 窗口保持 1100×740
- **THEN** 壳设置里落两笔：`appWindow:vcp` 与 `appWindow:pdf`，各自的宽高互不串味
- **AND** 启动器自己那一份记在 `launcherWindow` 下，不与任何应用共用

#### Scenario: SH-009 最大化时不记假位置
- **WHEN** 把窗口最大化后记下窗口状态
- **THEN** 记下的是"最大化"，不带 x/y
- **AND** 下次恢复用默认尺寸而不是屏幕外那组坐标；取消最大化后记的才带 x/y

#### Scenario: SH-010 每个应用在任务栏是自己的一个条目
- **WHEN** 看某应用窗口的任务栏身份
- **THEN** 身份是 `dev.xyzwp.airship.<应用 id>`，两个应用的身份必然不同
- **AND** 启动器自己的身份是 `dev.xyzwp.airship`，不带应用 id 后缀

### Requirement: 应用窗口里壳只添三样东西
标题栏、内容区的留白、主题变量。剩下的全是应用自己的事。

#### Scenario: SH-011 应用窗口的标题栏念得出"飞船 / 应用名"
- **WHEN** 打开 vcp 的窗口
- **THEN** 标题栏左端读得到「飞船」，其后跟着「vcp」
- **AND** 标题栏那三颗键各有可读名称（最小化 / 最大化或还原 / 关闭）

#### Scenario: SH-012 要不要留白由清单说了算
- **WHEN** 分别挂载 `flush: true` 与不写 flush 的应用
- **THEN** 前者内容区带 `app-window__body--flush`，壳不额外给内边距
- **AND** 后者由壳给内边距与滚动

#### Scenario: SH-013 组件还在路上时读得到占位
- **WHEN** 应用的组件 chunk 还没到位
- **THEN** 内容区读得到转圈占位，而不是一片空白

#### Scenario: SH-014 开了个不存在的应用，界面说清怎么修
- **WHEN** 请求挂载一个没有注册的应用 id
- **THEN** 读得到「没有注册这个应用：<id>」
- **AND** 紧跟一行提示，说去检查 `apps/<id>/app.ts` 是否存在、id 是否与目录名一致
