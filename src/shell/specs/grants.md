# grants

## Purpose
路径授权：哪条路径能读、哪条能写、用户经对话框给出去的许可怎么算。
规则原文见 [架构](../../../docs/architecture.md) §6.2，这本册子把它钉成可执行的结果。

### Requirement: 应用自己的地盘自由读写
每个应用在 userData 下有 `data/` 与 `cache/` 两份目录。

#### Scenario: GR-001 自己目录里的文件直接读得到
- **WHEN** 应用读自己 `data/` 里一个存在的文件
- **THEN** 拿到内容；读 `cache/` 同样直接给
- **AND** 没声明 `dialog` 也能读写自己目录，两条不互相牵扯

#### Scenario: GR-002 别的应用的地盘读不到也写不进
- **WHEN** vcp 试着读写 `apps/pdf/data/` 下的路径
- **THEN** 拒，原因读得到「没有读取权限：<路径>（只能读应用数据目录，或先用文件对话框选中它）」
- **AND** 写同样被拒，原因是「没有写入权限：<路径>（只能写应用数据目录，或用另存为对话框选定目标）」

#### Scenario: GR-003 越界拼路径在解析这一步就挡住
- **WHEN** 应用把 `..` 拼进 `resolveInData` 的段里，想跳出自己目录
- **THEN** 拒，原因读得到「路径越界：../x 不在<id> 的数据目录内」
- **AND** 想借共享区跳出也一样：原因里念出那个命名空间名

### Requirement: 共享命名空间声明了才碰得到
#### Scenario: GR-004 声明过的共享区可读写，未声明的拒
- **WHEN** 一个声明了 `library` 的应用解析共享区里的路径
- **THEN** 给出 `<userData>/shared/library/...` 且能读写
- **AND** 没 `shared` 能力或没声明这个命名空间的应用走同一条路会被拒（措辞见 `bridge.md` BR-007）

### Requirement: 其余路径必须本次会话里用户显式选中
#### Scenario: GR-005 对话框选中的文件才读得到
- **WHEN** 用户经"打开文件"选中一个应用目录外的文件
- **THEN** 这个路径立刻可读，目录本身仍不可读（只授了文件那一层）
- **AND** 没被选中的第二个路径读不到

#### Scenario: GR-006 选中目录，后代跟着可读
- **WHEN** 用户经"选择文件夹"选中一个目录
- **THEN** 该目录与其下任意深度的路径都读得到

#### Scenario: GR-007 要输出落在源文件同目录的应用，得显式请求父目录授权
- **WHEN** 带 `grantParentDir` 的文件选择完成后
- **THEN** 选中文件的父目录也进了可读集合（"输出文件已存在"这类校验才查得到）
- **AND** 不带这个选项时只授文件本身

#### Scenario: GR-008 另存为只开放选中的那一个写入目标
- **WHEN** 用户经"另存为"选定一个路径
- **THEN** 那个路径可写，它所在目录的**另一个**文件仍不可写
- **AND** 同目录被授权了**读**，好让外部命令写完能回读校验

#### Scenario: GR-009 授权条数查得到，给诊断用
- **WHEN** 启动器问某应用现在被授权了多少条
- **THEN** 返回读与写两个计数，与上面几步给出去的许可一致
