# proc-tools

## Purpose
子进程与外部工具：能跑什么、从哪找到它、输出怎么回到应用。
这是最危险的一条能力线（不变量 I-7），所以白名单的来历只有两个：**壳发现的**、**用户指定并通过校验的**。

### Requirement: proc 只跑白名单里的可执行文件
#### Scenario: PT-001 白名单外的东西跑不了
- **WHEN** 应用拿一个壳没发现、用户也没指定的 exe 发起调用
- **THEN** 拒，原因读得到「不允许执行 <exe>：可执行文件必须先由壳发现或用户在设置里指定（见 tools.ts 的白名单规则）」
- **AND** 一次性调用与后台任务两条路都一样拒

#### Scenario: PT-002 一次性调用返回完整结果
- **WHEN** 应用跑一条会自己结束的短命令
- **THEN** 拿到退出码、结束信号（正常结束为 null）、stdout 与 stderr 全文
- **AND** 这条不往窗口推分块事件，只有最终结果

#### Scenario: PT-003 后台任务的输出分块推回，中文不被劈成半字
- **WHEN** 一条真在跑的命令持续输出含中文的内容
- **THEN** 归属窗口按到达顺序收到分块，拼起来与原文一致，没有出现替换字符
- **AND** 任务结束时收到一条带最终结果的事件，之后同一个 jobId 不再出现在任务列表里

#### Scenario: PT-004 同一应用内任务标识重复会被拒
- **WHEN** 用同一个 jobId 起两条任务
- **THEN** 第二条拒，原因读得到「任务标识重复：<jobId>（同一个应用内要唯一）」
- **AND** 另一个应用用同一个 jobId 不受影响（归属不同）

#### Scenario: PT-005 停止任务：在跑的才停得掉
- **WHEN** 应用停一个任务标识
- **THEN** 在跑的返回 true 并立刻收到它的结束事件（信号 SIGKILL）
- **AND** 不在跑的返回 false，不报错也不产生事件

### Requirement: 工具怎么找到，是壳的知识
壳内置一张工具表（ffmpeg、wslc），应用只能声明"我要用哪一个"。

#### Scenario: PT-006 发现按固定顺序试
- **WHEN** 依次存在环境变量指定、用户指定、PATH 里的同名文件、已知安装位置
- **THEN** 用的是最靠前的那一个：环境变量 > 壳设置里用户指定的 > PATH > 该工具的已知安装位置

#### Scenario: PT-007 发现到了就进白名单，立刻跑得起来
- **WHEN** 壳把某个工具定位到一个真实文件
- **THEN** 同一条路径随后能被 proc 直接调用，不需要用户再指定一遍

#### Scenario: PT-008 这台机器上没有这个工具
- **WHEN** 所有候选位置都没有
- **THEN** 问路径的应用拿到 null（界面据此显示"不可用"），并且日志里留一条 warn 说清试过哪些位置

#### Scenario: PT-009 用户手动指定要过校验
- **WHEN** 指定一个不存在的路径，或指定一个 `-version` 输出里没有版本字样的文件
- **THEN** 前者回「文件不存在：<路径>」，后者回一句说明没认出这个工具的版本字样并念出输出开头
- **AND** 两种都**不**写进设置、**不**进白名单

#### Scenario: PT-010 应用只能问自己声明过的工具
- **WHEN** 应用问一个没写在自己清单 `tools` 里的工具路径
- **THEN** 拒，原因读得到「<id> 没有声明 <tool> 工具（要用它就在 apps/<id>/app.ts 的 tools 里声明）」
- **AND** 问一个壳的工具表里根本没有的名字，听到的是「壳不认识的工具：<名字>（壳的工具表只有 ffmpeg / wslc）」
