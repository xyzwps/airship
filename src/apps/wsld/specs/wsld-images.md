# wsld-images

## Purpose
容器台「镜像」页：从 `wslc images --format json` 读进来、一行报哪几样、搜索与排序与汇总怎么说，
以及页上那两个动作（拉取 `pull` / 删除 `rmi [-f]`）——命令怎么发、提示怎么说、取消与互斥怎么算、
被占用时怎么升到"强制删除"。
拉取的分层实时进度（要靠伪终端那一层）与镜像源改写本期不做。

### Requirement: 摆出来的就是本机有的镜像
数据只来自 `wslc images --format json` 这一条命令。字段名首字母大写、数字写成字符串、
同一镜像 ID 可以占好几行，这些都是 wslc 的实际形态；应用不自己拼数字，也不按 ID 猜该合并谁。

#### Scenario: IM-001 停在镜像页就自动加载一次
- **WHEN** 本机有镜像，切到「镜像」页
- **THEN** 不用点任何东西，wslc 那侧收到 `images --format json` 这一条命令
- **AND** 本机的镜像逐条摆出来，与手敲 `wslc images` 看到的行一一对应

#### Scenario: IM-002 一行报的只有这几样
- **WHEN** 停在「镜像」页看任一行
- **THEN** 读得到 `仓库名:标签`、大小、被引用情况
- **AND** 下面那行小字读得到短 ID 与创建时间，形如"ID aaef90e06523 · 创建 2026-05-13 10:21"

#### Scenario: IM-003 引用数写成字符串还是写成数字都读得出
- **WHEN** 同一个镜像，wslc 一次把它写成 `"Containers":"2"`，一次写成 `"Containers":2`
- **THEN** 两种写法下那一行都读得到"被 2 个容器引用"

#### Scenario: IM-004 引用数读不成数字时按没人用说
- **WHEN** 那一行的引用数写着 `N/A`、写着空串，或干脆没有这个字段
- **THEN** 那一行读得到"未被容器引用"
- **AND** 界面不说解析失败，这一行也不消失

#### Scenario: IM-005 没有标签的镜像有自己的说法
- **WHEN** 本机有一个仓库名与标签都写着 `<none>` 的镜像
- **THEN** 那一行读得到"无标签 · <短 ID>"，不是把 `<none>` 直接甩给用户
- **AND** 只有仓库名而标签是 `<none>` 时，这一行说的就是这个仓库名本身

#### Scenario: IM-006 同一镜像的两个标签占两行
- **WHEN** 一个镜像在本机有两个标签
- **THEN** 列表里是两行，名称分别是两个 `仓库:标签`
- **AND** 这两行的短 ID 与被引用数一模一样，界面不按 ID 把它们并成一行

#### Scenario: IM-007 创建时间与大小按人能读的样子写
- **WHEN** wslc 把创建时间写成 `2026-05-13 10:21:49 +0800 GMT+8`
- **THEN** 那一行读得到本地时刻"2026-05-13 10:21"，大小照 wslc 给的写法读（如 `4.45MB`）
- **AND** 这段时刻解析不动时，那一行把 wslc 写的话原样显示出来，不空着也不报错

### Requirement: 拉取一个引用只发那一条命令
引用先去掉首尾空白再拼进去；不用 `-q`，因为详细输出末尾那行 `Status:` 能区分
"真下载了新东西"和"本机本来就最新"，值得给用户两句不同的话。

#### Scenario: IM-008 拉取只发一条 `pull <引用>`
- **WHEN** 在拉取框里写一个引用（前后多打了空格）并点「拉取」
- **THEN** wslc 那侧收到 `pull <引用>`，引用前后的空白没被带进命令
- **AND** 除此之外不多发一条命令

#### Scenario: IM-009 框里是空的就什么都不发
- **WHEN** 拉取框空着或只有空格，用户在框里按回车
- **THEN** 读得到"请先输入要拉取的镜像引用，例如 docker.1ms.run/library/redis:7。"
- **AND** wslc 那侧一条命令都没收到，「拉取」那颗键也点不动

#### Scenario: IM-010 回车等同于点拉取
- **WHEN** 在拉取框里写完引用按回车
- **THEN** 与点「拉取」一模一样：发出 `pull <引用>`，进行中的标记与提示区同步开始

#### Scenario: IM-011 新下载的报"已拉取"
- **WHEN** `wslc pull` 以退出码 0 结束，输出里写着 `Status: Downloaded newer image for X`
- **THEN** 提示读得到"已拉取 X"
- **AND** 列表随后自己刷新一次，只补发一条 `images --format json`

#### Scenario: IM-012 本来就最新的报"已是最新"
- **WHEN** 拉的是本机已有的镜像，输出里写着 `Status: Image is up to date for X`
- **THEN** 提示读得到"X 已是最新"，不说"已拉取"
- **AND** 列表同样只刷新一次

#### Scenario: IM-013 没有 Status 行也照样收尾
- **WHEN** `wslc pull` 成功退出，但输出里一行 `Status:` 都没有
- **THEN** 提示按"已拉取 X"说
- **AND** 界面不说解析失败，也不挂错误条

#### Scenario: IM-014 拉错了能停，停了就是没发生
- **WHEN** 拉取正在进行，用户点那颗只在拉取期间看得见的「取消」
- **THEN** 提示读得到"已取消拉取 X"，界面不挂错误条
- **AND** 那个拉取进程被终止，列表不刷新

### Requirement: 删除一次只交一个引用
`wslc rmi A B C` 实测遇到第一个失败就停手，剩下的根本不被处理 —— 所以一行就是一个引用。
强制删除是真把镜像从磁盘上拿走、留下的容器再也起不来，那是破坏性动作，平时不给。

#### Scenario: IM-015 删除前先问一句，没被占用的说清只取消标签
- **WHEN** 在一个没被容器引用的行上点删除
- **THEN** 问话里读得到"确定要删除镜像引用 X？"与"如果这个镜像还有其它标签，这一步只会取消当前标签。"
- **AND** 答"取消"时 wslc 一条命令都没收到

#### Scenario: IM-016 被引用的镜像在问话里就把话说完
- **WHEN** 在一个正被 N 个容器引用的行上点删除
- **THEN** 问话里多一句"该镜像正被 N 个容器引用，这样删除会被拒绝，届时可再选择强制删除。"
- **AND** 这一句只是预告：答"删除"发的仍是不带 `-f` 的 `rmi <引用>`

#### Scenario: IM-017 删干净了怎么说
- **WHEN** `rmi`（或 `rmi -f`）以退出码 0 结束
- **THEN** 提示读得到"已删除 X"，列表刷新一次后那一行没了
- **AND** 这一行的键回到"删除"

#### Scenario: IM-018 被占用拒绝后那一行换个键
- **WHEN** 常规删除被拒绝，stderr 里是 `must force` 或 `unable to remove repository reference` 那一类
- **THEN** 那一行的键换成强制删除那一档：悬停说明与无障碍名称都是"强制删除镜像引用（wslc rmi -f）"，图标改用危险色
- **AND** 错误条末尾追加一句"该镜像正被容器使用，再点一次「强制删除」才能把它从磁盘上移除。"

#### Scenario: IM-019 别的失败不给这个选项
- **WHEN** 删除失败的原因是找不到镜像（`WSLC_E_IMAGE_NOT_FOUND`）或别的错误
- **THEN** 那一行的键仍是删除那一档（悬停说明"删除镜像引用（wslc rmi）"，不带危险色），错误条里也没有那句追加的话

#### Scenario: IM-020 强制删除是第二次显式动作
- **WHEN** 已经升级到"强制删除"的那一行被再次点击并在问话里答"强制删除"
- **THEN** 问话里读得到"该镜像正被 N 个容器引用，强制删除后这些容器将无法再次启动。"
- **AND** 这时才发出 `rmi -f <引用>`；答"取消"时 wslc 那侧什么都没收到

#### Scenario: IM-021 一次只删一个引用
- **WHEN** 一个镜像有两个标签，用户删掉其中一行
- **THEN** 只发出一条 `rmi <那一行的引用>`，不是把两个标签一起交上去
- **AND** 另一行照旧留在列表里

#### Scenario: IM-022 无标签镜像删的是它自己
- **WHEN** 在"无标签 · <短 ID>"那一行上发起删除
- **THEN** wslc 那侧收到的是 `rmi <镜像 ID>`，不是 `rmi <none>:<none>`

#### Scenario: IM-023 手动刷新不冲掉强制那一档
- **WHEN** 某行已经变成"强制删除"，用户点了刷新而它仍被容器引用
- **THEN** 刷新前后这一行都停在强制删除那一档（悬停说明不变），中间不闪回删除那一档
- **AND** 不用把常规删除再失败一次才重新拿到这个选项

#### Scenario: IM-024 占用消失了就收回这个入口
- **WHEN** 某行原本是"强制删除"，刷新后它不再被任何容器引用
- **THEN** 键回到删除那一档（悬停说明回到"删除镜像引用（wslc rmi）"、危险色收回），界面不再提供 `-f` 这条路

### Requirement: 同一时刻只有一个动作在跑
拉取与删除共用一把闩；中途列表被换掉会让用户点在被冲掉的行上，所以操作期间一律不刷新。
一个动作接着一个动作时，屏幕上同时挂着旧结果和新结果会让人误读，旧话一律让位。

#### Scenario: IM-025 期间别的动作点不动
- **WHEN** 有一次拉取或删除正在进行
- **THEN** 「拉取」那颗键与每一行的删除键都是禁用态
- **AND** 硬点第二下也不会让 wslc 那侧多出第二个进程

#### Scenario: IM-026 操作期间不读列表
- **WHEN** 有一次拉取或删除正在进行，用户点「刷新」
- **THEN** 期间不会发出 `images --format json`，列表还是原来那几行

#### Scenario: IM-027 动作一结束一切照常
- **WHEN** 拉取或删除收尾（成功、失败、取消都算）
- **THEN** 「拉取」与各行删除键恢复可用，刷新照常发出 `images --format json`

#### Scenario: IM-028 开始新动作就清掉旧提示
- **WHEN** 上一次的绿色提示或红色错误条还挂着，用户开始下一次拉取或删除
- **THEN** 那两处同时空出来，不再与这一轮的结果同屏

#### Scenario: IM-029 失败说的是清洗后的一句话
- **WHEN** 动作失败，wslc 在 stderr 里写了错误描述、`错误代码:` 与那句"欢迎提 issue"
- **THEN** 错误条读得到错误描述与错误代码，读不到样板话
- **AND** 绿色提示空着，列表还是上一次成功时那几行

### Requirement: wslc 的输出形态怎么变都读得进
无镜像时输出是空的；正常输出是每行一个对象；同一批数据也可能被排成 JSON 数组或带缩进的整块。
读不懂的行要说清是哪一行，而且说的是「镜像」。

#### Scenario: IM-030 空输出不是错误
- **WHEN** 本机一个镜像都没有，wslc 一个字都没输出
- **THEN** 界面不出现错误条
- **AND** 汇总位置读得到"本机还没有镜像"

#### Scenario: IM-031 排版变了行也还在
- **WHEN** 同一批镜像被排成每行一个对象、JSON 数组或带缩进的整块 JSON
- **THEN** 界面列出的镜像行数与字段一种不多一种不少

#### Scenario: IM-032 读不懂的行要说清是哪一行
- **WHEN** wslc 的输出里有一行不是有效的镜像 JSON
- **THEN** 错误条读得到是第几行，以及那一行的原文片段
- **AND** 说的是"镜像"这类数据读错了，不是含糊的一句"解析失败"

#### Scenario: IM-033 读失败不冲掉已经看见的列表
- **WHEN** 上一次加载成功，这一次 `wslc images` 以非 0 退出码失败
- **THEN** 列表还是上一次那几行，一行的内容都没被清空
- **AND** 错误条同时挂出来，下次加载成功它就没了

#### Scenario: IM-034 刷新没读完不叠加下一次
- **WHEN** 一次读取还在进行，又点了一次「刷新」
- **THEN** 这一轮被直接跳过，wslc 那侧不会同时挂着两条 `images`，界面不闪断

### Requirement: 找一个镜像不用翻页，顺序与汇总说的是全量
搜索只在已经读回来的数据里挑，一次进程都不起。默认顺序只为"清理时先看有用的"服务：被引用的在前。
镜像不像容器那样起起停停，所以这一页不做自动轮询。

#### Scenario: IM-035 输入即过滤，且不惊动 wslc
- **WHEN** 在搜索框（提示语写着"搜索仓库名 / 标签 / ID"）里输入某镜像的仓库名、标签或 ID 的任一片段
- **THEN** 列表立刻只剩匹配的那些行，匹配不区分大小写、不要求从头开始
- **AND** 输入与清空的全过程里，wslc 那侧一条命令都没多收到

#### Scenario: IM-036 一个都没匹配上
- **WHEN** 搜索词把每一行都筛掉了
- **THEN** 读得到"没有匹配的镜像"，界面不出现错误条

#### Scenario: IM-037 被引用的排前面
- **WHEN** 本机既有被容器引用的镜像，也有没人引用的镜像
- **THEN** 被引用的那些行排在前面
- **AND** 同一档内按仓库名、再按标签排，都不区分大小写

#### Scenario: IM-038 汇总报的是全量
- **WHEN** 本机有 N 个镜像、其中 M 个有标签、K 个正被容器引用
- **THEN** 读得到"共 N 个镜像 · M 个有标签 · K 个正被容器引用"
- **AND** 输入搜索词只剩几行时，这三个数不变

#### Scenario: IM-039 停在页面上不会自己变
- **WHEN** 停在「镜像」页，谁都不点
- **THEN** 页面底部读得到"· 镜像不会自动变化，拉取或删除后会自动更新列表"
- **AND** 除了进来那一次，wslc 那侧不再收到别的 `images` 请求
