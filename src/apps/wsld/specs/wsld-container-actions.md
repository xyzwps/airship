# wsld-container-actions

## Purpose
对单个容器做的四个动作：启动 / 停止 / 重启 / 删除。行上只有一颗"启动"，其余三颗在选中后的详情头部。
容器怎么列出来、详情长什么样在 `wsld-containers.md`(CL)，错误文案的清洗规矩在那本册子里已写死，
这里只引用不重复。

### Requirement: 四颗键与 `wslc` 子命令一一对应，认 ID 不认名字
启动 / 停止 / 重启 / 删除分别就是 `start` / `stop` / `restart` / `remove`，
参数是容器 ID 加动作本身，不带别的选项；删除正在运行的容器必须 `-f`（实测不加会被引擎拒绝）。

#### Scenario: CA-001 启动只发一条 `start <ID>`
- **WHEN** 按下一行上或详情头部的「启动」
- **THEN** wslc 那侧收到的命令行是 `start <容器ID>`，除此之外不多发一条
- **AND** 不弹确认框，按下去就直接发

#### Scenario: CA-002 停止只发一条 `stop <ID>`
- **WHEN** 在确认框里点了「停止」
- **THEN** wslc 收到的命令行是 `stop <容器ID>`，没有强杀、没有超时参数、没有第二个进程

#### Scenario: CA-003 重启只发一条 `restart <ID>`
- **WHEN** 在确认框里点了「重启」
- **THEN** wslc 收到的命令行是 `restart <容器ID>`

#### Scenario: CA-004 删除已停止的容器发 `remove <ID>`
- **WHEN** 容器已停止，在确认框里点了「删除」
- **THEN** wslc 收到的命令行是 `remove <容器ID>`，不带 `-f`

#### Scenario: CA-005 删除运行中的容器发 `remove -f <ID>`
- **WHEN** 容器正在运行，在确认框里点了「删除」
- **THEN** wslc 收到的命令行是 `remove -f <容器ID>`

#### Scenario: CA-006 用 ID 不用名称
- **WHEN** 发起上述任何一条命令
- **THEN** 命令行里的容器参数永远是容器 ID，不是界面上更顺眼的容器名称
- **AND** 界面上一行连名称都没有（只认 ID）时，操作照常，发的还是那个 ID

### Requirement: ID 拿不到就一步都不迈
容器标识为空或只有空白时，四个动作谁都不许起进程。

#### Scenario: CA-007 空 ID 不发任何命令
- **WHEN** 对一条没有 ID 的容器行按下「启动」
- **THEN** wslc 那侧一条命令都没收到，连进程都不起
- **AND** 界面停在原地、不崩，读得到"容器 ID 不能为空。"

### Requirement: 全局一次只有一个动作在飞
同一时刻整个页面只允许一个生命周期操作；第二次触发直接被忽略，不排队、不叠加。
动作在飞的时候不读列表，免得界面在操作中途被换血。

#### Scenario: CA-008 操作进行中，所有操作键一律按不动
- **WHEN** 有一次启动 / 停止 / 重启 / 删除正在进行
- **THEN** 每一行的「启动」与详情头部四颗键、还有「刷新」全部是禁用态
- **AND** 发起操作的那一行同时转起忙碌圈

#### Scenario: CA-009 二次触发被吞掉，wslc 只听见一条命令
- **WHEN** 一次操作还没结束，又去点第二颗（或狂点同一颗）
- **THEN** 第二次触发不产生任何 wslc 调用，界面上也不报错
- **AND** 第一个操作结束后，按钮统一恢复可用

#### Scenario: CA-010 操作期间不发出 `wslc list`
- **WHEN** 一次操作正在进行中，用户点「刷新」
- **THEN** 期间一条 `list -a --format json` 都不发，wslc 只听见那一次操作命令
- **AND** 操作结束（成败都一样）后，列表照旧能刷

### Requirement: 成功就刷一次，失败就原地站着
这四个命令成功时静默（退出码 0、无输出），失败时 stderr + 非 0；界面跟着这个分工走。

#### Scenario: CA-011 操作成功 → 列表补刷一次，状态跟着变
- **WHEN** 一次操作以退出码 0 结束
- **THEN** 界面只补发一次 `list -a --format json`，列表与"最近刷新"时刻随之更新
- **AND** 那一行与详情头部的新状态同批出现：启动后读得到"运行中"，停止后读得到"已停止"

#### Scenario: CA-012 删除成功 → 那一行消失，详情收回
- **WHEN** 删除操作成功
- **THEN** 刷新之后这个容器从列表里消失
- **AND** 右侧详情回到那句引导话（见 CL-013）

#### Scenario: CA-013 操作失败 → 不补刷，旧数据原样留着
- **WHEN** 一次操作以非 0 退出码失败
- **THEN** 界面不补发任何 `list`，列表还是上一次成功读回的样子
- **AND** 错误条挂出清洗后的文案（样板话已去掉，见 CL-024）

#### Scenario: CA-014 引擎拒绝要说清是谁
- **WHEN** 一次删除被引擎拒绝，stderr 里有错误描述与 `错误代码:` 一行
- **THEN** 错误条读得到那句描述与错误代码那一行，连成一句
- **AND** 读不到"欢迎提 issue"那句样板话

### Requirement: 按钮可用性只是体验优化
启动 / 停止对状态重复的调用返回退出码 0，重启会把已停止的容器直接启动 ——
可用性规则不是正确性前提。

#### Scenario: CA-015 运行中的容器，「启动」按不动
- **WHEN** 选中的容器正在运行
- **THEN** 详情头部的「启动」是禁用态，「停止」可按

#### Scenario: CA-016 已停止的容器，「停止」按不动
- **WHEN** 选中的容器已停止
- **THEN** 详情头部的「停止」是禁用态，行上的「启动」可按

#### Scenario: CA-017 「重启」与「删除」永远可按
- **WHEN** 容器任意状态下被选中
- **THEN** 「重启」「删除」都可按；对已停止的容器点「重启」，它会被直接启动

### Requirement: 会打断容器里跑着的东西，先问一句
停止 / 重启 / 删除都算危险动作，点下去之前各问一句；「启动」不打断任何东西，照旧一键就走。

#### Scenario: CA-018 点删除先问一句（已停止的措辞）
- **WHEN** 对一个已停止的容器点「删除」
- **THEN** 问话里读得到"确定要删除容器 <名称>？此操作不可恢复。"
- **AND** 答"取消"时 wslc 一条命令都没收到，列表与详情纹丝不动

#### Scenario: CA-019 运行中的容器多一句红话
- **WHEN** 对一个正在运行的容器点「删除」
- **THEN** 问话里除了上面那句，还多一行"该容器正在运行，将强制停止并删除（wslc remove -f）。"
- **AND** 措辞按点下去这一刻的运行状态决定

#### Scenario: CA-020 点「停止」先问一句
- **WHEN** 对一个正在运行的容器点「停止」
- **THEN** 问话里读得到"确定要停止容器 <名称>？容器里正在跑的进程会被终止（wslc stop）。"
- **AND** 答"停止"才发出 `stop <容器ID>`

#### Scenario: CA-021 点「重启」先问一句
- **WHEN** 对任意状态的容器点「重启」
- **THEN** 问话里读得到"确定要重启容器 <名称>？重启期间容器里的进程会中断（wslc restart）。"
- **AND** 答"重启"才发出 `restart <容器ID>`

#### Scenario: CA-022 答"取消"什么都不发生
- **WHEN** 任一句问话被答成"取消"
- **THEN** wslc 那侧一条命令都没收到，选中行与详情从头到尾没换过
- **AND** 按钮不受影响，下一次动作照旧能发起

### Requirement: 行是认 ID 续用的，不是每次重建
刷新时按容器 ID 续用同一行，只换数据 —— 行上的忙碌状态与按钮得活得过刷新。

#### Scenario: CA-023 刷新不重建行，按钮不闪断
- **WHEN** 列表刷新前后容器都还在
- **THEN** 那一行还是同一个界面元素：不消失、不重建，忙碌圈不闪断
- **AND** 状态变了时只有徽标与状态文字跟着换

### Requirement: 界面只给这四个动作
没有强杀键、没有多容器批量 —— 界面不该让人找得到入口。

#### Scenario: CA-024 找不到强杀，也找不到批量
- **WHEN** 把容器页行上与详情头部翻个遍
- **THEN** 读不到任何"强杀 / kill"字样的键或菜单项
- **AND** 无处勾选多行做批量：所有操作都是对一个容器一个一个来
