# wsld-logs

## Purpose
容器详情里「日志」那一档：两种读法（查看日志 / 实时日志）各自的命令、校验、上屏节奏与会话收尾。
"读历史"和"盯新行"是两件不同的事，界面上也各走各的命令、各有一份文本。
容器起停动作本身在 `wsld-container-actions.md`(CA)，错误文案清洗在 `wsld-containers.md`(CL)。

### Requirement: 两种读法各发各的命令，不许混
一次性读法拼成 `logs [-t] [-n 行数] <容器>`，实时读法拼成 `logs -f [-t] --since <Unix 秒> <容器>`，
顺序固定、实时那条永远不带 `-n`（实测没有 `--since` 的 `-f` 会把全部历史先冲出来，那就不是"实时"）。

#### Scenario: WL-001 「查看日志」拼出一条一次性命令
- **WHEN** 勾了"显示时间戳"、行数选了"最近 500 行"，点「查看日志」
- **THEN** wslc 那侧收到 `logs -t -n 500 <容器>`，顺序就是这么写的
- **AND** 这条命令里读不到 `-f`，跑完这一次就结束

#### Scenario: WL-002 选"全部"时不发出 `-n`
- **WHEN** 行数那一格选到"全部"，点「查看日志」
- **THEN** 收到的命令是 `logs <容器>`，一个行数控件的值都不带
- **AND** 历史有多少给多少

#### Scenario: WL-003 「实时日志」拼出带起点的跟随命令
- **WHEN** 勾了"显示时间戳"，点「实时日志」
- **THEN** 收到的命令是 `logs -f -t --since <点下这一刻的 Unix 秒> <容器>`
- **AND** 这条命令里读不到 `-n`

#### Scenario: WL-004 没勾时间戳就两条命令都不带 `-t`
- **WHEN** "显示时间戳"没勾上，分别走两种读法
- **THEN** 「查看日志」发的是不带 `-t` 的读法，「实时日志」也是不带 `-t` 的跟法

#### Scenario: WL-029 没起点就没有实时
- **WHEN** 一次实时请求拿不到正的起点时刻
- **THEN** 进程一次都不起，界面上不出现"其实在倒历史"的半截实时
- **AND** 提示位置读得到那句要起点的话

### Requirement: 发命令之前先把输入校验干净
容器标识不能为空；查看模式的行数不能越界；实时必须有起点。
非法输入在启动进程之前就被挡下，免得换回 wslc 那 8 行没有价值的 usage 噪音（退出码 1）。

#### Scenario: WL-005 空容器标识不起进程
- **WHEN** 触发任一种读法时手里其实没有可用的容器标识
- **THEN** wslc 那侧一条命令都没收到，连进程都不起
- **AND** 提示位置读得到"容器标识不能为空。"，界面不崩

#### Scenario: WL-006 越界的行数不拿去问 wslc
- **WHEN** 一次读取要用的行数是负数或超过上限的整数
- **THEN** wslc 那侧一条命令都没收到
- **AND** 提示位置读得到那句说明行数区间的中文，而不是 wslc 的 usage 输出

#### Scenario: WL-007 行数只能从那几档里选
- **WHEN** 打开「行数」那一格
- **THEN** 只选得到最近 100 / 200 / 500 / 1000 / 2000 行与"全部"这几档
- **AND** 选了哪一档，发出去的 `-n` 就是那个数；界面上没有一处能敲进越界数字的地方

### Requirement: 日志文本进界面
输出按行拆开进只读文本区：中间空行是日志的一部分，单行过长只截显示，不截存储。

#### Scenario: WL-008 中间空行原样保留
- **WHEN** 读回的日志里夹着空行，末尾还挂着换行符产生的空尾巴
- **THEN** 空行在显示区占一行，不因为"没字"被抹掉
- **AND** 末尾那个空尾巴不被算成一行，状态栏的"共 N 行"因此不虚高

#### Scenario: WL-009 超长行截断并留话
- **WHEN** 有一行超过了显示宽度上限
- **THEN** 这一行只贴出前一段，末尾跟着读得到"…（本行过长，已截断显示）"

### Requirement: 勾了时间戳才动行首
只有本次请求带了 `-t`，才把行首的 UTC 时间戳换成本地时分秒；其余情况一个字都不改行内容。

#### Scenario: WL-010 时间戳换成本地时分秒
- **WHEN** 勾了"显示时间戳"，wslc 回的行首是一串 UTC 时间戳
- **THEN** 行首被换成本地 `时:分:秒.毫秒` 那种写法，行里剩下的内容原样跟在后面

#### Scenario: WL-011 解析不了就原样站着
- **WHEN** 开了时间戳，而某一行行首不是能认出的时间戳格式
- **THEN** 这一行原样显示，不被改写、也不被吞掉

### Requirement: 实时逐行到屏，慢日志也不装死
实时读到一行就往外递、绝不攒到进程结束；行没读完整之前不上屏，读完了立刻长一行。

#### Scenario: WL-012 实时是一条一条长出来的
- **WHEN** 实时日志正在收，输出一块一块地到（最后一块停在半行上）
- **THEN** 已经完整的行一条一条出现在文本区，不是等进程结束才一次贴出全部
- **AND** 那半行不占位，等补齐了才成为一行

#### Scenario: WL-013 状态栏跟着新行走
- **WHEN** 实时日志很久只来一两条
- **THEN** 状态栏"共 N 行 · 最近加载 时:分:秒"里的行数与时刻跟着新行往后走

### Requirement: 只显示最近 2000 行，丢掉的要说
实时挂着跑一夜不至于吃满内存；丢掉的行数在状态栏说得出口。

#### Scenario: WL-014 超过两千行就丢最早的
- **WHEN** 界面已显示的行突破 2000 行上限
- **THEN** 屏幕上始终留着最近 2000 行，最早的那批被请出去
- **AND** 状态栏读出"已丢弃最早的 N 行"，N 是累计丢掉的行数

### Requirement: 空日志是正常，不是错误
实测已退出或从未启动的容器，`logs` 返回退出码 0 + 空输出；界面把它说成"没内容"，不谎报成失败。

#### Scenario: WL-015 空输出读得到那句"没有输出"
- **WHEN** 读取一个已停止（或从未启动）的容器，读回 0 行
- **THEN** 提示位置读得到"这个容器目前没有任何输出。"
- **AND** 不出现错误条——退出码 0 就是它真的没话

### Requirement: 错误进提示位，不进日志文本区
读取失败（非 0 退出码）时，清洗后的一句话写进日志区下方的提示，日志文本区不被污染。

#### Scenario: WL-016 读失败给的是人话，不是半截日志
- **WHEN** 一次读取以非 0 退出码失败（stderr 有错误描述、`错误代码:` 与那句样板话）
- **THEN** 提示位置读得到清洗后的那句话，读不到"欢迎提 issue"那套样板话
- **AND** 文本区保持失败前的样子，错误文本没被当成日志行贴进去

### Requirement: 同一时刻只挂一个日志进程
两种读法共用一把闩：读的过程中点任何日志入口都被吞掉，不让两个进程抢同一个容器。

#### Scenario: WL-017 读进行中，日志入口全体僵住
- **WHEN** 一次日志读取（查看或实时）正在进行
- **THEN** 「查看日志」「实时日志」都不响应第二次点击，行数与时间戳那两处同时是禁用态
- **AND** wslc 那侧不会另起第二条 `logs` 进程抢同一个容器

### Requirement: 只有运行中的容器可以实时
对已停止的容器点「实时日志」要灰掉，并把为什么写在悬停说明里；要翻旧日志用「查看日志」。

#### Scenario: WL-018 停止的容器开不了实时
- **WHEN** 选中一个已停止的容器，停在「日志」这一档
- **THEN** 「实时日志」是禁用态，悬停说明读得到"容器没在运行，看不了实时日志；要翻旧日志请用「查看日志」。"
- **AND** 「查看日志」不受这条限制，已停止的容器照样翻旧账

#### Scenario: WL-019 运行状态一变，能不能实时跟着变
- **WHEN** 一次操作把当前容器从运行中变成已停止
- **THEN** 「实时日志」随之变成禁用态，悬停说明跟着改口
- **AND** 正在跑的实时就地收尾，提示位置读得到"已停止实时日志。"

### Requirement: 新一轮实时从空白开始，停下时保留已显示的行
"从现在起"不该混进上一趟的历史；停下时眼睛看到的都留着。

#### Scenario: WL-020 开实时之前先把屏幕擦净
- **WHEN** 刚用「查看日志」读回一批历史，再点「实时日志」
- **THEN** 文本区先清成空白，上一趟读到的历史一行都不残留
- **AND** 屏幕从点下去这一刻的新行开始长

#### Scenario: WL-021 点「停止实时」只停不收摊
- **WHEN** 实时日志正在进行，点了「停止实时」
- **THEN** 文本区已显示的行全数保留，提示位置读得到"已停止实时日志。"
- **AND** 停下之后 wslc 那侧这个跟随进程被终止（收到带 SIGKILL 的结束）

### Requirement: 实时结束要分情况说话
容器被停止时 wslc 自己安静退场、不留一句"容器已结束"，这句话界面得替它说。

#### Scenario: WL-022 实时自然结束 → 说清多半是容器停了
- **WHEN** 用户没点「停止实时」，这一趟跟随走到了尽头（退出码 0），期间收到过新行
- **THEN** 提示位置读得到"实时日志已结束（容器多半已停止）。"
- **AND** 已上屏的行留在文本区

#### Scenario: WL-023 全程一行都没来
- **WHEN** 一次实时走到结束而期间一条新行都没收到
- **THEN** 提示位置读得到"实时日志已结束，期间没有新日志。"

#### Scenario: WL-024 实时里读出失败
- **WHEN** 一次实时因 wslc 非 0 退出而结束
- **THEN** 提示位置换回清洗后的错误文案，而不是那句"容器多半已停止"

### Requirement: 换容器、切页签，日志会话各归各
日志缓冲属于"这一个容器这一次会话"，串台比少看更糟。

#### Scenario: WL-025 换容器 = 旧会话立刻收摊
- **WHEN** 旧容器正在跑实时，列表里点了另一个容器
- **THEN** 旧容器的实时被终止，它的行、状态与丢弃计数一并清空，新容器的日志区是空白
- **AND** 「实时日志」能不能按，按新容器的运行状态重新决定

#### Scenario: WL-026 切回「详情」只停实时不清屏
- **WHEN** 实时进行中（或已经停掉），切到「详情」再切回「日志」
- **THEN** 正在跑的实时停下来，但已显示的行留着，切回来还在原位
- **AND** 切这两档不另起 `logs` 进程

### Requirement: 自动滚到底默认开着，关掉不挡新行
新来的行要不要拉着视图往下跑由用户说了算；关掉不等于不收。

#### Scenario: WL-027 默认自动滚到底
- **WHEN** 进入「日志」这一档，什么都没动过
- **THEN** "自动滚到底"处于已勾选状态

#### Scenario: WL-028 关掉自动滚，新行仍进缓冲
- **WHEN** 取消勾选"自动滚到底"，实时继续跑
- **THEN** 新行照样落进文本区、状态栏的行数照样往上走
