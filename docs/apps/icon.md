# 一个 app 的图标要求

一个应用**固定两张图标**，都放应用目录根（产包后就是包根），文件名靠约定、不进清单：

| 文件 | 格式 | 给谁用 | 用在哪 |
| --- | --- | --- | --- |
| `icon.png` | **只认 PNG** | 窗口内部 | 标题栏左上角那枚 15×15 记号 |
| `icon.ico` | 多尺寸 ICO | Windows 外壳 | 任务栏按钮、固定到任务栏那颗、桌面/开始菜单快捷方式 |

两张都由应用作者**存成文件**随仓库走；产包只搬进包根，任何环节都不转格式。

## `icon.ico` 的标准形状

- 7 帧方图 **16 / 24 / 32 / 48 / 64 / 128 / 256**，每帧 32 位色，帧内是 **PNG 压缩**（不是老式 BMP + AND 掩码）
- 整档 10K ~ 65K，大头在 128/256 两帧（仓内 12 张实测全部一致，最重的 books 52.8K）
- 对作者的下限按教程页那句：**16 / 32 / 48 / 256 齐**。帧数不齐、尺寸不成套，产包不拦（见"判据边界"）
- 为什么非 `.ico` 不可：外壳取图标只认**文件系统路径**——不认 asar、不认 `airship://`，也不认源图那档格式

## 三条规矩

1. **图标不进清单**：`iconPath`、`icon`、`order` 都是被驳回过的键（PK-004 / AP-007）——图标是文件，顺序是应用之间的事。
2. **全仓不转图标格式**：改图在外部工具里重出这两张，别指望产包或安装流水替你转，也别再往那两条流水里加转换步骤。
3. **runtime 侧不认识任何具体应用**：加应用不动 runtime 一个文件，图标也一样只随包走。

## 判据边界

- 代码判据只有一份：`@airship/contract` 的 `packageRules.ts`（`ICON_NAME` / `ICON_PATTERN` / `RETIRED_ICON_PATTERN` / `WINDOWS_ICON_NAME`）——产包侧与注册侧调同一批函数，报错措辞也由它供，别在界面或 NSI 里另写一份。
- 册子钉可观察结果：包根有没有这两份（PK-004 / PK-036 / PK-039）、源图留着退场格式点名拒绝（AP-001 / AP-002）。
- **没有用例钉的**：ico 的帧集合与尺寸（只验头四字节 `[0,0,1,0]`）；真机上那颗好不好看归 `just shot`。

## 造新应用时的自查

```
src/apps/<id>/icon.png     那张源图（建议 ≤512×512，不套底板，颜色烘进图里）
src/apps/<id>/icon.ico     自备多尺寸 ico：16/24/32/48/64/128/256，32bit，PNG 帧
src/apps/<id>/main.tsx     createAirshipApp({ …, icon: './icon.png' })
```

目录根留着 `icon.svg` 那一批就是 AP-002 那句点名拒绝。补图时记得把旧的那张删掉。

## 更新日志

- **2026-11-26 的收窄**：源图从前接受 `icon.svg` / `png` / `jpg` / `jpeg` / `webp`，现在**只认 `icon.png`**，那批格式不是"忽略"而是**点名拒绝**。理由是 PNG 就是 ico 帧的原生编码（仓内 12 张 ico 的 7 帧实测全是 PNG-in-ICO），一张母版贯通窗口与外壳；而多档扩展名只带来"到底该放哪张"的分歧，没有换来任何真机收益。即纯为了方便。
